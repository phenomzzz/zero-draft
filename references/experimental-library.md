# Experimental library art direction

## Explicit mode, not normal delivery policy

Triggers: "experimental mode", "library stress test", or explicit award-style / maximal exploration. Ordinary creation and ordinary component-library requests keep normal scope. Goal: a memorable, coherent experiential concept whose ambition survives into the main output. It is an experimental prototype, not a production-readiness claim.

Facts stay honest, essential content stays reachable and readable, controls stay operable, reduced motion is respected and hazardous flashing is avoided. Everything else (page sequence, grid, navigation presentation, motion restraint, CTA funnels) is open; do not silently restore conventional defaults under the label of good UX. Review only on the brief's declared platforms: a desktop-only experiment is not reviewed for touch or small screens.

During generation load this file, [motion-recipes.md](motion-recipes.md) and, when a component library is in play, the [reuse rules](motion-and-media.md#reusing-demos-and-component-libraries). From [design-profile.md](design-profile.md) use only the house-signature list and the collaboration preferences. De-slop, action density, scaffolding and copy references are review gates at the representative slice and final synthesis, not generation inputs. Respect explicit exclusions and disclose actual exposure; isolation does not prevent convergence, the divergence work below does.

## House signature

Each concept may use at most two of the house-signature traits in design-profile.md, each with a reason from the subject, assets or brief. A component library's demo palette, type stack and eyebrow/heading shells are placeholder styling; never inherit them as project tokens.

## Diverge on the visual world, then the journey

Build a divergence matrix before any layout. Rows:

- Typographic genre and width (condensed sans, wide grotesque, serif display, script, monospace, custom lettering, typography-only).
- Value and palette strategy (light, dark, mid-tone, duotone, full-colour imagery, single-ink).
- Image treatment (cut-out, full-bleed, illustrated, typographic-only, generated texture, data-as-image).
- Grid model (none, editorial columns, spatial canvas, single object, index, layered planes).
- Navigation model (long scroll, rooms, index, map, timeline, single object state).
- Motion physics (springy, weighted, mechanical, scrubbed, cinematic cuts, near-still).

Each concept takes a different cell in at least four rows, including typography and value. Assign every concept's cells before rendering any. With subagents authorized, render concepts in parallel isolation at the lead's model; working alone, write all concept specs before rendering the first.

Render each concept as a style tile before page layout, with the real wordmark, one real headline, a real data row and one real asset: type and palette in use, one control, one motion clip or frame strip. Compare tiles side by side at thumbnail size; if two read as the same author, replace one. Token swaps do not count as tiles.

Give each surviving tile a journey: spatial model, reading order and the library mechanisms that shape it. Palette or font swaps on a shared journey are not different concepts. A required content representation (for example a portrait grid) stays fixed; its surroundings, typography and transitions do not. Let mechanisms set typography and space, not only motion: text-on-path, split-flap, ASCII, scramble or shader families can anchor a concept. Investigate components before settling on a familiar page; do not sprinkle effects on a preselected template. The lead assigns cells and chooses; subagents may render tiles, survey or implement bounded parts, never set the direction. Choose autonomously when authorized; there is no mandatory approval pause.

## Spike the riskiest idea at full ambition

Before choosing, implement the leading concept's most ambitious mechanism at full strength in its real context, time-boxed. Record what actually broke (measured frame time, input conflict, legibility with real names) before reducing it; a reduction names the measured problem it solves.

Keep the chosen direction on the main experience. The workbench holds rejected or unresolved alternatives, not the selected concept's best parts.

## Account for meaningful use

Classify each integrated adaptation by what shipped, not the demo name:

- **Microinteraction:** localized hover, count, underline or entry effect.
- **Component behavior:** meaningful filtering, drawer, tab, menu or gallery behavior.
- **Structural experience:** a mechanism shaping a region's composition, navigation, spatial relationship or story progression.

A complex source reduced to a fade is a microinteraction. Repeated instances are not independent mechanisms; generic matching behavior is not source reuse. Link source files to target code and an observable state, with identifiable adapted geometry or control logic.

For each structural claim, record the source's defining parameters (pinning, scrub, snap, spatial extent, duration, input ownership) beside the shipped values, plus a short recording. A pinned scrubbed wipe that ships as a 260 ms slide is classified by what shipped.

For each important use ask what recognizable experience disappears if it becomes a static block. Judge breadth across mechanisms and regions, integration depth and visible impact together; no quota establishes success, and several subtle effects do not substitute for substantive exploration when that is the request.

## Adaptation before rejection

Classify candidates: irrelevant to facts/task, unavailable source, tested technical incompatibility, promising adaptation, aesthetic rejection, or deferred by budget. Distinguish observation, hypothesis and attempted result. Missing semantics, resize cleanup or placeholder-media mismatch are work, not vetoes. Rejections cite observed evidence on the declared platforms; "competes with the existing typography", "harder to compare names" or "lacks a touch default" on a desktop-only brief are positions to test against an alternative arrangement. Check whether a photographic demo truly depends on photography before rejecting it for illustration, type, video or character imagery. A disabled prototype is not a failed performance test. Attempt the strongest promising cases within scope; never force every candidate or invent facts to justify an effect.

## Finish the experiment honestly

Show the selected concept working, not a catalog count. Verify coordinated input/scroll/transform ownership, lifecycle, resizing, keyboard access, reduced motion and graphics fallbacks in context on the declared platforms. Performance claims need measurement; WebGL, pinned sequences, custom navigation and animated type are not prohibited. Fix or scope measured issues without flattening the whole concept.

Keep original artifacts. Report micro/component/structural use separately, main-site versus workbench-only studies, rejection evidence and unresolved risk. Compare tiles, selected concept and shipped result against the experiment's goals and the house signature. Package checks do not validate aesthetic ambition or novelty.
